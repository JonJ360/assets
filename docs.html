What this is

Equipment and vehicle register for Fargo, Bismarck, and Grand Forks. Tracks what you own, where it is, who has it, what you paid, and what you sold it for. Two prices per asset — purchase and sell. No transaction ledger, no depreciation; that stays in GP and with Devon. Single-file vanilla HTML/JS, Supabase backend, GitHub Pages deployable.

Setup — 4 steps

  1. Create a Supabase project. Separate from AR CRM and Ignite Care for data isolation.
  2. Run the SQL below in the SQL editor.
  3. Paste credentials into BAKED_CONFIG at the top of the script in index.html — SUPABASE_URL and SUPABASE_ANON_KEY (Settings → API).
  4. Push to GitHub Pages. The header chip flips from LOCAL — NOT SAVED to SUPABASE LIVE.
Until credentials are baked in, the app runs in local mode with sample data and nothing persists on reload. Intentional — evaluate the workflow before standing up the backend.

SQL schema

-- Asset Register v1.01
create extension if not exists "pgcrypto";

create table if not exists assets (
  id             uuid primary key default gen_random_uuid(),
  unit_no        text,
  name           text not null,
  category       text,
  make           text,
  model          text,
  year           int,
  vin            text,
  serial         text,
  plate          text,
  entity         text,
  location       text,
  status         text default 'Active',
  assigned_to    text,
  purchase_date  date,
  purchase_price numeric(14,2),
  sale_price     numeric(14,2),
  vendor         text,
  funding        text,
  lender         text,
  loan_payoff    numeric(14,2),
  reg_expires    date,
  insured        boolean default false,
  title_status   text,
  title_note     text,
  state          text,
  title_number   text,
  gvw            numeric(10,0),
  on_dep_schedule boolean default false,
  dep_location   text,
  origin         text,
  notes          text,
  doc_url        text,
  created_at     timestamptz default now(),
  updated_at     timestamptz default now()
);

create index if not exists idx_assets_entity   on assets(entity);
create index if not exists idx_assets_status   on assets(status);
create index if not exists idx_assets_location on assets(location);
create index if not exists idx_assets_unit     on assets(unit_no);

-- RLS: anon-key access, same posture as the AR CRM.
alter table assets enable row level security;
create policy "anon all assets" on assets
  for all using (true) with check (true);
Security. That policy lets anyone with the anon key and the URL read and write. Fine for an unlisted Pages URL; it is not access control. This table holds VINs, payoff balances, and lender names — add Supabase Auth and restrict the policy to authenticated before real data goes in.

Unit # convention

Set in BAKED_CONFIG at the top of index.html:

UNIT_PREFIX: { "Fargo":"F", "Bismarck":"B", "Grand Forks":"G" },
UNIT_SEP: "-",     // "F-107". Set "" for "F107", " " for "F 107".
UNIT_PAD: 0        // 0 -> "F-107". 3 -> "F-107" stays, "F-7" becomes "F-007".

Change the letters or separator here and the Next button, the warnings, and sorting all follow. Existing records are not rewritten — the format only applies to numbers generated from that point on.

The parser reads F-107, F107, SMI 107, and bare 107, so legacy formats import and sort correctly without cleanup.

Migrating your spreadsheets

  1. Save each Excel sheet as CSV.
  2. Import / Export tab → choose the file.
  3. Columns auto-map from your headers (Unit #, Serial No, Purchase Price, Sold For, etc.). Fix what it got wrong; set unwanted columns to ignore.
  4. Only Asset name is required. Rows with a blank name are skipped.
  5. Import creates new records — it never updates existing ones. Import each sheet once.

Dates accept YYYY-MM-DD, M/D/YYYY, or M/D/YY. Currency accepts $ and commas. Unrecognized statuses default to Active.

Technical notes

  • Single file, no build step, no CDN dependencies. Supabase via the PostgREST endpoint with fetch — no SDK.
  • Only the Supabase authentication session is cached in localStorage; asset data is not. Live mode reads and writes Supabase on every action; local mode is memory only.
  • Every save re-reads the table in live mode, so concurrent users converge on refresh. Last write wins.
  • Responsive to phone width — tables collapse to labeled stacks. Visible keyboard focus, Esc closes the panel, reduced-motion respected.

Not in v1.01

Depreciation · file attachments (link out via doc_url) · maintenance scheduling by hours or mileage · edit audit trail · GP sync · user accounts.
